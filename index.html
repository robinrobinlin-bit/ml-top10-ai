一、機器學習總覽

機器學習（Machine Learning, ML）是讓電腦從資料中學習規律，並把學到的規律用於預測、分類、推薦、分群或決策支援的技術。和傳統程式最大的差別在於，傳統程式多半由工程師明確寫出規則，而機器學習則是先準備資料、定義目標、選擇模型，再讓模型從歷史樣本中自動調整參數。當資料量變大、規則複雜、變化快速時，機器學習能補足人工規則難以維護的缺點。

本報告選出十個最常見、最適合建立基礎觀念的演算法：線性迴歸、邏輯迴歸、決策樹、隨機森林、Gradient Boosting / XGBoost、支援向量機、KNN、朴素貝氏、K-Means 與神經網路。這十個演算法橫跨監督式學習、非監督式學習、集成學習、機率模型、相似度方法與深度學習。只要能理解它們的基本想法，後續學習資料科學、AI 工程、雲端 AI、RAG 或生成式 AI，都會有比較穩定的基礎。

閱讀本報告時，建議不要只背演算法名稱，而要用「問題類型」來思考：我要預測一個數字？我要判斷是或否？我要把客戶分群？我要處理文字？我要追求可解釋性還是準確率？資料量大不大？欄位是否乾淨？特徵是否需要標準化？這些問題比單純問「哪個演算法最強」更重要。實務上沒有永遠最好的模型，只有最符合資料、目標與限制的模型。

三、學習前必懂核心觀念

資料與標籤

機器學習的資料通常由特徵與標籤組成。特徵是輸入，例如年齡、金額、點擊次數、文字詞頻、影像像素；標籤是答案，例如房價、是否流失、是否詐欺、產品類別。監督式學習需要標籤，非監督式學習不需要標籤。若標籤定義不穩定，例如不同人對「高風險」的判斷不同，模型也會學到混亂的規則。

訓練、驗證與測試

訓練集用來讓模型學習，驗證集用來調整模型與參數，測試集用來模擬未知資料的表現。若把測試集拿來反覆調參，測試集就不再客觀。實務上常用交叉驗證降低單次切分造成的偶然性，尤其資料量不大時更重要。

過度擬合與欠擬合

欠擬合是模型太簡單，連訓練資料也學不好；過度擬合是模型太依賴訓練資料細節，訓練表現很好但新資料表現差。好的模型不是訓練分數最高，而是在未知資料上穩定。正則化、剪枝、交叉驗證、增加資料、降低模型複雜度，都可用來改善過度擬合。

評估指標

回歸常看 MAE、MSE、RMSE、R²；分類常看 accuracy、precision、recall、F1、ROC-AUC；分群常看輪廓係數與業務可解釋性。不同問題應選不同指標，例如疾病篩檢更重視 recall，垃圾郵件分類可能同時重視 precision 與 recall。

特徵工程

特徵工程是把原始資料轉成模型更容易學習的形式。常見方法包括標準化、one-hot encoding、日期拆解、文字向量化、異常值處理、缺失值補齊、特徵交互作用、聚合統計。模型表現常常不是靠換演算法，而是靠更好的特徵定義與資料品質。

線性迴歸 Linear Regression

監督式學習 / 回歸｜連續數值預測

模型類型監督式學習 / 回歸
主要用途連續數值預測
數學直覺y = b0 + b1*x1 + b2*x2 + ... + e；核心是讓預測值與真實值的誤差平方和最小。
實務例子房價預測：輸入坪數、屋齡、離捷運距離、樓層、區域平均成交價，輸出預測房價。也可用在銷售預測、流量預估、成本估計。

概念定位

線性迴歸（Linear Regression）是學習機器學習時非常重要的基礎模型。它代表一種思考方式：不要先追求複雜，而是先建立可理解、可驗證、可與業務溝通的基準模型。很多專案一開始就使用深度學習或很複雜的集成模型，表面上看起來先進，但如果沒有基準模型，就很難知道提升來自資料品質、特徵工程，還是模型本身。線性迴歸的價值在於讓我們把問題拆清楚，先確認資料是否有訊號，再決定是否需要更複雜的方法。

任務類型與資料準備

從任務類型來看，線性迴歸屬於「監督式學習 / 回歸」，主要用途是「連續數值預測」。在資料科學流程中，它通常出現在建模階段，但真正影響效果的往往是建模前的資料理解與資料準備。若資料欄位定義不清、樣本代表性不足、標籤錯誤、缺失值未處理，任何演算法都可能得到漂亮但錯誤的結果。因此學習線性迴歸時，應同時學會檢查資料分布、建立訓練集與測試集、使用交叉驗證，以及用合適指標評估模型。

數學與模型直覺

數學直覺可以簡化成：y = b0 + b1*x1 + b2*x2 + ... + e；核心是讓預測值與真實值的誤差平方和最小。 公式並不是為了增加難度，而是幫助我們理解模型如何把輸入特徵轉成輸出結果。初學者可先掌握三件事：第一，模型的輸入是特徵；第二，模型會把特徵轉換成某種分數、距離、規則或機率；第三，模型透過訓練過程讓預測結果更接近真實答案。只要掌握這個框架，後續看不同演算法時就不會迷路。

實務案例拆解

實務例子：房價預測：輸入坪數、屋齡、離捷運距離、樓層、區域平均成交價，輸出預測房價。也可用在銷售預測、流量預估、成本估計。 這類案例的關鍵不是把資料丟進模型就結束，而是要先定義預測目標、資料時間窗、訓練資料來源與模型上線後的使用方式。例如預測客戶流失時，若今天才知道客戶已經取消合約，就不能把取消後才產生的欄位放進訓練資料，否則會造成資料洩漏。資料洩漏會讓測試結果看似非常準確，但實際上線後表現大幅下降。

優點、限制與適用場景

線性迴歸的優點通常包括：概念相對清楚、訓練流程容易建立、可以作為基準模型、在某些資料條件下速度快且穩定。缺點則可能包含：假設條件較強、對資料尺度或雜訊敏感、在高度非線性或特徵交互作用複雜時表現不足。選擇模型時不能只看排行榜，而要看專案需求：若主管需要解釋原因，可解釋性比極致準確率重要；若是即時推薦系統，推論速度和維運成本也很重要。

常見錯誤與檢查清單

常見錯誤包含：沒有切分訓練集與測試集、在全資料上做標準化後才切分、只看 accuracy 不看 precision / recall / F1、忽略不平衡資料、把相關性誤解成因果關係、沒有檢查異常值與缺失值。學習線性迴歸時，建議每次練習都記錄資料來源、特徵欄位、目標欄位、前處理方式、模型參數、評估指標與觀察結論，這樣才是真正的研讀與實作。

實作練習建議

若要動手練習，可以準備一份小型 CSV 資料集，先用 pandas 做資料摘要，再用 scikit-learn 建立模型。流程是：讀取資料、處理缺失值、切分訓練測試、建立 pipeline、訓練模型、輸出評估指標、畫圖檢查預測結果。完成後再改變特徵、調整參數、比較不同模型。透過這樣的循環，線性迴歸不只是課本上的名詞，而會變成能解決問題的工具。

數學直覺可以簡化成：透過資訊增益、Gini impurity 或平方誤差選擇最佳切分點，使分裂後群組更純。 公式並不是為了增加難度，而是幫助我們理解模型如何把輸入特徵轉成輸出結果。初學者可先掌握三件事：第一，模型的輸入是特徵；第二，模型會把特徵轉換成某種分數、距離、規則或機率；第三，模型透過訓練過程讓預測結果更接近真實答案。只要掌握這個框架，後續看不同演算法時就不會迷路。

實務例子：貸款審核：依收入、信用分數、負債比、工作年資建立問答式規則，輸出核准、拒絕或人工審查。 這類案例的關鍵不是把資料丟進模型就結束，而是要先定義預測目標、資料時間窗、訓練資料來源與模型上線後的使用方式。例如預測客戶流失時，若今天才知道客戶已經取消合約，就不能把取消後才產生的欄位放進訓練資料，否則會造成資料洩漏。資料洩漏會讓測試結果看似非常準確，但實際上線後表現大幅下降。

K 最近鄰（K-Nearest Neighbors）是學習機器學習時非常重要的基礎模型。它代表一種思考方式：不要先追求複雜，而是先建立可理解、可驗證、可與業務溝通的基準模型。很多專案一開始就使用深度學習或很複雜的集成模型，表面上看起來先進，但如果沒有基準模型，就很難知道提升來自資料品質、特徵工程，還是模型本身。K 最近鄰的價值在於讓我們把問題拆清楚，先確認資料是否有訊號，再決定是否需要更複雜的方法。

任務類型與資料準備

從任務類型來看，K 最近鄰屬於「基於實例的學習」，主要用途是「相似度分類、推薦、簡易回歸」。在資料科學流程中，它通常出現在建模階段，但真正影響效果的往往是建模前的資料理解與資料準備。若資料欄位定義不清、樣本代表性不足、標籤錯誤、缺失值未處理，任何演算法都可能得到漂亮但錯誤的結果。因此學習K 最近鄰時，應同時學會檢查資料分布、建立訓練集與測試集、使用交叉驗證，以及用合適指標評估模型。

數學與模型直覺

數學直覺可以簡化成：不顯式訓練參數，而是在預測時計算新資料與歷史資料的距離，取最近 K 個鄰居投票或平均。 公式並不是為了增加難度，而是幫助我們理解模型如何把輸入特徵轉成輸出結果。初學者可先掌握三件事：第一，模型的輸入是特徵；第二，模型會把特徵轉換成某種分數、距離、規則或機率；第三，模型透過訓練過程讓預測結果更接近真實答案。只要掌握這個框架，後續看不同演算法時就不會迷路。

實務案例拆解

實務例子：推薦商品、判斷手寫數字、依歷史相似客戶預測風險。 這類案例的關鍵不是把資料丟進模型就結束，而是要先定義預測目標、資料時間窗、訓練資料來源與模型上線後的使用方式。例如預測客戶流失時，若今天才知道客戶已經取消合約，就不能把取消後才產生的欄位放進訓練資料，否則會造成資料洩漏。資料洩漏會讓測試結果看似非常準確，但實際上線後表現大幅下降。

優點、限制與適用場景

K 最近鄰的優點通常包括：概念相對清楚、訓練流程容易建立、可以作為基準模型、在某些資料條件下速度快且穩定。缺點則可能包含：假設條件較強、對資料尺度或雜訊敏感、在高度非線性或特徵交互作用複雜時表現不足。選擇模型時不能只看排行榜，而要看專案需求：若主管需要解釋原因，可解釋性比極致準確率重要；若是即時推薦系統，推論速度和維運成本也很重要。

常見錯誤與檢查清單

常見錯誤包含：沒有切分訓練集與測試集、在全資料上做標準化後才切分、只看 accuracy 不看 precision / recall / F1、忽略不平衡資料、把相關性誤解成因果關係、沒有檢查異常值與缺失值。學習K 最近鄰時，建議每次練習都記錄資料來源、特徵欄位、目標欄位、前處理方式、模型參數、評估指標與觀察結論，這樣才是真正的研讀與實作。

實作練習建議

若要動手練習，可以準備一份小型 CSV 資料集，先用 pandas 做資料摘要，再用 scikit-learn 建立模型。流程是：讀取資料、處理缺失值、切分訓練測試、建立 pipeline、訓練模型、輸出評估指標、畫圖檢查預測結果。完成後再改變特徵、調整參數、比較不同模型。透過這樣的循環，K 最近鄰不只是課本上的名詞，而會變成能解決問題的工具。

若要動手練習，可以準備一份小型 CSV 資料集，先用 pandas 做資料摘要，再用 scikit-learn 建立模型。流程是：讀取資料、處理缺失值、切分訓練測試、建立 pipeline、訓練模型、輸出評估指標、畫圖檢查預測結果。完成後再改變特徵、調整參數、比較不同模型。透過這樣的循環，神經網路 / 深度學習不只是課本上的名詞，而會變成能解決問題的工具。

五、十個小專題實作模板

每學一個演算法都做一個小作品，輸出問題定義、資料欄位、模型、評估指標、圖表與改進方向。

房價預測專題

使用線性迴歸建立房價預測。資料欄位可包含坪數、屋齡、樓層、捷運距離、行政區、停車位與交易年月。先畫散佈圖觀察坪數與房價的關係，再處理行政區類別欄位，最後用 MAE 與 RMSE 評估。報告重點不是只寫分數，而是解釋哪些特徵影響最大，以及殘差是否在高價物件特別大。

客戶流失預測

使用邏輯迴歸或隨機森林預測客戶是否會在下個月流失。資料可包含使用天數、最近登入、客服抱怨、月費、合約型態與加購服務。應特別注意不平衡資料，因為流失客戶通常比例較低。評估時除了 accuracy，也要看 recall 與 precision，並用不同門檻比較攔截名單大小。

貸款核准規則

使用決策樹建立可解釋的貸款審核模型。特徵可包含收入、負債比、信用分數、工作年資與是否有逾期紀錄。完成模型後，把樹的路徑轉成文字規則，例如「信用分數高且負債比低則核准」。此專題適合練習模型解釋、剪枝與避免過度擬合。

設備故障預測

使用隨機森林或 XGBoost 預測設備是否可能故障。特徵可包含溫度、電流、振動、錯誤碼次數、上次維修距今天數與負載。實務上資料常有時間順序，因此切分資料時應用早期資料訓練、後期資料測試。若能提前預測故障，可降低維修成本與停機風險。

廣告點擊率預測

使用 XGBoost 預測使用者是否會點擊廣告。特徵可包含廣告類型、曝光時間、裝置、使用者興趣、歷史點擊率與頁面位置。此問題通常資料量大且類別欄位多，適合練習 one-hot encoding、target encoding、交叉驗證與 ROC-AUC。

文件主題分類

使用朴素貝氏、邏輯迴歸或 SVM 將新聞分成政治、科技、財經、運動等類別。先做斷詞、移除停用詞、轉成詞袋或 TF-IDF，再比較不同模型。此專題能理解文字資料和表格資料不同之處，也能體會特徵維度很高時線性模型的優勢。

會員分群

使用 K-Means 將會員依消費金額、購買頻率、最近一次購買距今天數分成不同群組。先標準化特徵，再用 elbow method 或 silhouette score 選擇 K 值。最後不是只交出群號，而要替每群命名，例如高價值客、價格敏感客、沉睡客。

相似商品推薦

使用 KNN 或相似度方法建立簡單推薦。資料可以是商品特徵、用戶評分或購買紀錄。先定義距離或相似度，再找出最相近的商品或用戶。此專題適合理解「模型不一定要訓練很多參數」。

影像分類入門

使用簡單神經網路或卷積神經網路辨識手寫數字或簡單圖片。重點是理解輸入層、隱藏層、輸出層、損失函數與反向傳播。初學者不必一開始追求大型模型，可先用小資料集觀察訓練 loss 與驗證 accuracy 的變化。

模型比較報告

使用同一份資料比較線性模型、決策樹、隨機森林與 XGBoost。固定訓練測試切分與評估指標，再比較準確率、訓練時間、解釋性與維運難度。真正的專案不是只跑一個模型，而是需要在多個候選方案中做取捨。

七、常見問答 FAQ

初學者應該先學哪三個演算法？

建議先學線性迴歸、邏輯迴歸與決策樹。線性迴歸讓你理解數值預測與誤差；邏輯迴歸讓你理解機率與分類門檻；決策樹讓你理解規則、切分與可解釋性。

為什麼不能直接學深度學習？

可以學，但若完全沒有傳統機器學習基礎，容易只會呼叫套件而不理解資料、特徵、評估與過度擬合。深度學習需要更多資料、算力與調參經驗。

模型準確率很高就代表可以上線嗎？

不一定。要確認測試資料是否乾淨、是否有資料洩漏、是否符合未來資料分布、是否能承受錯誤成本、是否能監控模型漂移。

表格資料最常用哪個模型？

在許多表格資料問題中，Random Forest、Gradient Boosting、XGBoost、LightGBM 類模型常有很強的表現。但線性模型仍適合作為基準或需要透明度的場景。

分群結果如何判斷好不好？

分群不像分類有標準答案，因此不能只看數學分數。除了 silhouette score，也要看每群是否能被解釋、是否能對應業務行動、群組大小是否合理。

如何避免只會背名詞？

每學一個演算法都做一個小專題，並用同一份資料比較不同模型。把每次練習寫成報告：問題、資料、模型、指標、圖表、錯誤分析與改進。
